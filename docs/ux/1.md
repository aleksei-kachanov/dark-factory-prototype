**Agent:** ux-designer-darkfactory

## Summary

Two visible UI changes:
1. A new **Wind Dir** column added to `ForecastTable` for all regions (simulated + Austin)
2. **"Austin, TX"** added as a selectable region in `RegionSelector`

No new pages, no new routes, no navigation changes.

---

## State Grid

| State | RegionSelector | ForecastTable | Notes |
|-------|---------------|---------------|-------|
| Initial load (default region) | 6 buttons: Tropical, Arid, Temperate, Continental, Polar, **Austin, TX**. First button active. | 5 rows × 7 columns (Date, Condition, Temp °C, Temp °F, Humidity, Wind km/h, **Wind Dir**) | Austin, TX button is last |
| Simulated region selected | Selected region button active | Forecasts show simulated values; Wind Dir = one of 8 compass strings | `windDirection` field populated |
| Austin, TX selected | "Austin, TX" button active; other buttons enabled | 5 rows with real data; Wind Dir populated | Real temperature, summary, wind data |
| Loading (any region) | All buttons disabled | Previous forecast faded / loading indicator | `disabled` prop on RegionSelector |
| Error (upstream failure — Austin) | Austin, TX button active | Error message displayed: "Upstream weather service unavailable: ..." | `error` state in App.tsx |
| Error (any region, generic) | Region button still active | Error message displayed | Existing error handling unchanged |
| Austin, TX — partial data | "Austin, TX" button active | Fallback: `windDirection ?? '—'` renders dash | Guard in ForecastTable |

## Component Flows

### RegionSelector

**Before:**
- 5 buttons (tropical, arid, temperate, continental, polar)
- Label: `region.charAt(0).toUpperCase() + region.slice(1)` (inline)

**After:**
- 6 buttons (adds `austin`)
- Label: `REGION_LABELS[region]` from `types/weather.ts`
- `austin` renders as **"Austin, TX"** (not "Austin")
- Button order: Tropical | Arid | Temperate | Continental | Polar | **Austin, TX**
- No other changes to selection, active state, disabled state

### ForecastTable

**Before:**
- 6 columns: Date, Condition, Temp (°C), Temp (°F), Humidity (%), Wind (km/h)

**After:**
- 7 columns: Date, Condition, Temp (°C), Temp (°F), Humidity (%), Wind (km/h), **Wind Dir**
- Wind Dir cell: `{f.windDirection ?? '—'}` — dash fallback if null/empty
- Wind Dir header: `Wind Dir`
- Column is last (rightmost)
- No other changes to existing columns

## Accessibility

| Element | Requirement |
|---------|------------|
| New table header `<th>Wind Dir</th>` | No additional ARIA needed — inherits table semantics |
| Austin, TX button | `key="austin"`, text "Austin, TX" is descriptive; no additional ARIA needed |
| Wind Dir cell | Screen reader reads compass value (N, NE, etc.) or "—" as is — acceptable |

## Data Contract (null guard check)

| Field | Source | Null guard in UI |
|-------|--------|-----------------|
| `windDirection` | `WeatherForecastDto.windDirection: string` | `f.windDirection ?? '—'` in ForecastTable |
| Austin label | `REGION_LABELS['austin'] = 'Austin, TX'` | Always defined — `REGION_LABELS` is a complete `Record<Region, string>` |

## Not in Scope

- Wind direction icon/arrow
- Real-time data refresh
